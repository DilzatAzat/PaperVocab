# Windows 桌面验收

本文件是人工验收步骤，不是通过记录。下面所有系统交互项目初始状态均为 **待 Windows 实测**。浏览器预览、构建成功和单元测试不能代替桌面验收。

## 准备

- 在 Windows 10 或 11 x64 上记录系统版本、阅读器名称及版本、PaperVocab 版本或提交。
- 准备可复制英文文本的真实 PDF 和扫描 PDF。可复制样本建议同时含普通词、短语及 `RNA`、`AI` 等缩写。
- 在 PowerShell 运行 `./scripts/verify.ps1`；加 `-Bundle` 时生成 NSIS 安装包。任一命令失败即停止。
- `pnpm-workspace.yaml` 的 `allowBuilds` 只明确批准 esbuild 所需安装脚本。不要为了通过检查批准所有依赖脚本。
- 用 `pnpm tauri dev` 启动桌面程序，或运行 `src-tauri/target/release/bundle/nsis/` 中实际生成的 `*-setup.exe`。
- 在设置中填入自己的 Chat Completions 兼容 API Base URL、模型和密钥。API 返回成功前，不记录“真实 API 已验证”。mock 服务仅记录为 mock。

## 补齐真实 PDF 与 API 的最小验收

这些步骤应使用安装版，不能以宣传页预览或 mock 结果替代。每次记录安装包 SHA-256、系统、阅读器、API 服务名称与模型，以及测试时间；不记录密钥、Authorization 请求头或私有论文全文。

1. 在设置中确认实际保存且注册成功的快捷键（新安装默认 `Ctrl+Shift+L`，用户可能已改为其他组合，须使用实际配置）。打开真实可复制的英文 PDF，先手动复制一次，确认阅读器允许复制。选一个此前未收录的词，再按该快捷键；记录选区、浮窗原词、保存状态和真实 API 返回的释义。PDF 阅读器应仍保有焦点。再测试一个短语和一个专业缩写，核对保存文本准确。
2. 先复制一个易识别的旧词，取消所有 PDF 选区再按快捷键；必须提示没有新文本，词数和遇见数均不增加。扫描 PDF 也不能误收旧剪贴板。若阅读器自带 OCR，应记录其开启状态，不能据此声称软件实现了 OCR。
3. 使用自己已配置的 API 完成一次实际请求。记录协议为 OpenAI Chat Completions 兼容、服务商、模型、目标语言及成功时间；以应用显示成功释义和真实网络请求为证据，不仅看“密钥已配置”。测试会消耗 API 额度，使用公开测试词及较小预算。
4. 验证失败可恢复：在隔离测试账户断网后收一个新词，确认原词先保存且有可理解的失败提示；恢复网络，点重试，成功后核对同一条单词更新而非新增遇见。错误密钥测试使用专门测试配置，避免覆盖本人当前可用配置。限流、坏 JSON 与刻意乱序可用 mock 补充，但必须分别标注为 mock。
5. 再次取同一个已成功翻译的词，核对优先显示缓存、遇见数增加且复习数未变化。从托盘退出并重启，核对词和释义仍在。进入复习，先揭示释义，再评分；不认识 / 有点印象 / 认识分别产生下一次到期的 1 / 3 / 7 天规则，记录实际到期时间。
6. 主窗口关闭应保留托盘；托盘退出应使进程终止并释放快捷键。不同阅读器、焦点、图片和并发剪贴板仍需逐项执行上方清单，单次真实 PDF 成功不等于全平台兼容。

如果尚无可用 API 或无法完成调用，记录“真实 API 未运行”和具体原因；不要读取、导出或打印 Windows 凭据中的密钥来诊断。若测试发现缺陷，记录可复现步骤后修复并复验，不能只把清单勾成通过。

## 干净环境的完整安装与卸载

不要在用户现有词库所在账户上卸载来换取一条通过记录。优先用干净 Windows 虚拟机及快照；可用时也可用 Windows Sandbox。若没有可用隔离环境，完整卸载维持待验收，先完成不依赖它的项目。

1. 在干净 Windows 10/11 x64 环境，从正式主页下载安装包及对应 `SHA256SUMS.txt`，执行 `scripts/check-release.ps1`。记录文件大小、SHA-256 和签名状态。当前 `v0.1.0` 为未签名；如果签名接入后测试新版本，使用 `-ApplicationExe` 与 `-RequireSigned` 验证安装包和应用。
2. 用普通用户双击安装，检查提示、目标路径、开始菜单 / 桌面快捷方式与卸载条目。若缺少 WebView2，验证联网下载或明确失败；有 WebView2 的机器安装成功不能替代缺失运行时的检查。安装后从快捷方式启动，不应出现开发终端；签名版本还应单独检查实际安装的应用 EXE 与 `uninstall.exe` 的签名，不从 setup 签名推断内部文件均已签名。
3. 在该隔离账户配置专用测试 API，执行上述真实 PDF、一次复习、托盘退出及重启流程。记录数据目录中的词库实际位置；Tauri 按 `com.papervocab.app` 的应用数据路径创建 `papervocab.sqlite3`，不要把个人词库或凭据复制到代码仓库。
4. 从托盘完全退出，确认 `papervocab` 进程已终止。通过 Windows“已安装的应用”或安装目录中的卸载程序执行卸载，记录退出结果与提示。确认程序 EXE、卸载条目、开始菜单 / 桌面快捷方式实际是否移除，托盘及进程不存在，原快捷键不再触发。
5. 单独记录本地数据库目录是否保留，以及 Windows 凭据管理器中 PaperVocab 测试凭据是否保留；只检查存在性，不查看或截图密钥内容。当前项目没有承诺自动删除词库或凭据，不将“软件已卸载”写成“个人数据已全部清除”。
6. 重新安装同一包，核对能否启动及保留数据是否重新可用，记录结果。测试结束后从 Windows 凭据管理器手动删除隔离账户的测试凭据，撤销专用 API 密钥，并回滚虚拟机快照；这些清理仅限该隔离环境。

完整验收记录至少包含：包与哈希、系统 / 阅读器 / 模型、安装路径、真实取词和释义结果、重启后数据、复习到期时间、卸载后程序 / 快捷方式 / 数据 / 凭据各自状态、重装结果，以及未运行项。Windows 11 上的一次成功不能自动标记 Windows 10 或其他阅读器已通过。

## 官方配置依据

2026-09-27 只读核查 Tauri 2 官方页面：

- [Windows Installer](https://v2.tauri.app/distribute/windows-installer/)：Windows 上 `tauri build` 生成安装包，NSIS 是 setup exe；WebView2 是运行时要求。
- [Configuration Reference](https://v2.tauri.app/reference/config/)：`bundle.windows.nsis.installMode` 默认 `currentUser`，支持 `currentUser`、`perMachine`、`both`；构建目标包含 `nsis`。配置错误应由构建失败报告。
- [GitHub Pipeline](https://v2.tauri.app/distribute/pipelines/github/)：官方示例使用 `windows-latest` 和 Rust stable。项目 CI 直接运行 CLI、仅上传 Actions artifact，不创建 Release 或自动公开发布。

CI 上传位置为 `src-tauri/target/release/bundle/nsis/*.exe`。未显式指定 Rust target 时使用宿主 Windows x64 路径；显式使用 `--target x86_64-pc-windows-msvc` 会新增 target 子目录，需同步修改 artifact 路径。
